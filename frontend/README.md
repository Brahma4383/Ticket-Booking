# SuryaBooker frontend

The React client for the SuryaBooker API. It renders the search, the five
booking flows and the account pages, and it talks only to the Django backend
over `/api/`: there is no server-side code here and no database access. The
root [README](../README.md) explains how the front end, the API and
`schema.sql` fit together.

## Prerequisites

- Node 24. `.nvmrc` pins the major version, for `nvm use` and for CI.
- npm. `package-lock.json` is the only lockfile; do not add a pnpm or yarn one.

## Running it

```bash
npm install
cp .env.example .env
npm run dev                   # http://localhost:5173
```

The dev server binds to every interface (`server.host` in `vite.config.ts`),
so the `Network:` URL Vite prints opens the app on a phone on the same Wi-Fi.
The API is expected on port 8000; start it as the root README describes.

## Scripts

| Script | What it does |
|---|---|
| `npm run dev` | Starts the Vite dev server with hot reload. |
| `npm run build` | Typechecks with `tsc -b`, then bundles into `dist/` with Vite. A type error fails the build. |
| `npm run lint` | Runs oxlint with the rules in `.oxlintrc.json`. Warnings are printed; only errors fail. |
| `npm run preview` | Serves the last `dist/` build locally, to check it before deploying. |

There is no test suite yet; `lint` and `build` are the whole check.

## Environment

Copy `.env.example` to `.env`. Vite exposes only variables prefixed `VITE_`
to the browser, and everything in this file ends up in the bundle, so no
secret ever goes here.

The one variable is `VITE_API_URL`, and it is optional. When it is unset,
`src/services/api.ts` points every request at port 8000 on whichever host the
page was opened from: `http://localhost:8000/api` at your desk, and
`http://192.168.0.x:8000/api` when the same build is opened on a phone, where
`localhost` would have meant the phone itself. Set it to pin the API to one
address instead, which is what production wants when the API is mounted
behind the same domain as the site. A trailing slash is stripped.

## Folder map

```
src/
  main.tsx          Mounts <App /> and imports index.css.
  App.tsx           Every route. A booking flow's search lives in its query string.
  index.css         Tailwind entry point and the theme's CSS variables.
  assets/           Images bundled by Vite (the hero background).
  components/       Shared building blocks: Navbar, Footer, BookingLayout,
                    PaymentStep, TextField, SelectField, Modal, AuthModal, ChatWidget.
  components/ui/    shadcn primitives (button, dialog, select, tabs, ...),
                    generated by the shadcn CLI.
  constants/        Static content: nav menus, offers, popular routes, footer
                    columns, page copy, the train station list.
  hooks/            useAuth, useChat, useFormValidation, useStepHistory, useTheme,
                    useReveal, useScrolled.
  icons/            Hand-drawn SVG icon components on one 24x24 grid.
  lib/utils.ts      Re-exports cn for the shadcn components, which import it from here.
  pages/Home/       The landing page and its search panel.
  pages/account/    The signed-in traveller's bookings.
  pages/about/ ...  about, careers, newsroom, legal: standalone pages.
  pages/<mode>/     bus, train, plane, hotel, cab. One folder per booking flow:
                    index.tsx wires the steps, Step*.tsx is one screen each, and a
                    useXBooking hook (useBooking.ts for bus) holds the flow's state.
  services/         api.ts, then one file per API module: auth, account, bus, train,
                    plane, hotel, cab, chat, contact.
  types/            One file per API module, mirroring the JSON it returns.
                    api.types.ts is the error envelope; common and home hold UI types.
  utils/            Pure helpers: cn, currency, date, theme, validation.
```

## Conventions

- `@/` is `src/`. It is declared in `tsconfig.json`, `tsconfig.app.json` and
  `vite.config.ts`; imports use it rather than `../../`.
- A shadcn primitive is added with `npx shadcn add <name>`. `components.json`
  puts it in `src/components/ui/` and points its `cn` import at
  `@/lib/utils`. Commit the generated file.
- Every request goes through `apiGet` and `apiPost` in `src/services/api.ts`,
  which own the base URL, the bearer token and the error envelope. A failure
  throws an `ApiError` with the backend's `code`, `status` and `detail`:
  `isConflict` (409) means re-query, `needsSignIn` (401) means offer sign-in.
- Each travel mode has one `services/<mode>.services.ts` and one
  `types/<mode>.types.ts`. The types mirror the API response exactly, so the
  services pass responses straight through and only map ids on the way in.
- Forms validate locally with the pure rules in `src/utils/validation.ts`,
  run by `useFormValidation` on the first submit and live after that. The
  rules mirror the serializers, and the server still validates everything.

## Checks before a pull request

```bash
npm run lint
npm run build
```

Both must pass; the `frontend` job in `.github/workflows/ci.yml` runs the
same two after `npm ci`. Branching, commit messages and the pull request
process are in [CONTRIBUTING.md](../CONTRIBUTING.md); the root
[README](../README.md) covers the backend and the database.
